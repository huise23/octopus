# 余额查询功能规划文档

## 1. 功能概述

实现一个统一的余额查询功能，支持从多个中转软件（NewAPI、OneAPI等）获取渠道余额信息。

## 2. 需求分析

### 2.1 用户需求
- 自动获取各中转站点的余额信息
- 统一展示余额数据
- 支持多种中转软件
- 定期自动更新余额

### 2.2 业务价值
- 提供实时余额监控，避免服务中断
- 帮助用户了解资源消耗情况
- 支持成本管理和预算控制

## 3. 技术分析

### 3.1 现有架构分析

#### 渠道管理（Channel模型）
- **位置**: `internal/model/channel.go`
- **关键字段**:
  - `Type`: 渠道类型（OpenAI、Anthropic、Gemini等）
  - `BaseUrls`: 基础URL列表
  - `Keys`: 密钥信息（包含`TotalCost`字段）
  - `Proxy`: 代理设置

#### HTTP客户端
- **位置**: `internal/helper/channel.go`
- **方法**: `ChannelHttpClient()` - 支持系统代理和自定义代理

#### API调用框架
- **位置**: `internal/helper/fetch.go`
- **现有功能**: 支持获取模型列表（`FetchModels`）
- **支持类型**: OpenAI、Anthropic、Gemini

### 3.2 中转软件分析

#### NewAPI/OneAPI特性
1. **兼容性**: 提供OpenAI兼容的API接口
2. **余额查询**:
   - 通用接口: `GET /api/user/self` 或 `GET /api/balance`
   - 返回格式:
     ```json
     {
       "code": 0,
       "data": {
         "balance": 100.50,
         "quota": 1000000,
         "used_quota": 50000
       },
       "message": "success"
     }
     ```
3. **认证方式**: Bearer Token（与现有API Key相同）

#### 中转软件识别策略
1. **通过响应特征识别**:
   - 检查特定的响应头（如`X-NewAPI-Version`）
   - 检查错误响应格式
2. **通过URL模式识别**:
   - 常见路径: `/v1/chat/completions`
   - 特定端点存在性测试

### 3.3 实现方案

#### 方案一：扩展FetchModels框架
1. **优点**: 复用现有架构，一致性高
2. **缺点**: 需要修改核心fetch逻辑

#### 方案二：独立Balance查询模块
1. **优点**: 模块化设计，不影响现有功能
2. **缺点**: 需要重复实现HTTP客户端逻辑

**推荐方案**: 方案一，扩展现有框架

## 4. 技术难点

### 4.1 中转软件识别
- **难点**: 不同中转软件的特征识别
- **解决**: 设计探测机制，尝试调用多种可能接口

### 4.2 统一响应格式
- **难点**: 不同软件的余额数据格式各异
- **解决**: 定义统一的数据结构，进行适配转换

### 4.3 错误处理
- **难点**: 区分API错误、网络错误、权限错误
- **解决**: 分层错误处理，提供明确的错误类型

### 4.4 性能影响
- **难点**: 频繁查询可能影响系统性能
- **解决**:
  - 异步查询
  - 批量处理
  - 缓存机制

## 5. 数据模型设计

### 5.1 新增数据结构

```go
// BalanceResponse 统一的余额响应结构
type BalanceResponse struct {
    Balance      float64 `json:"balance"`       // 余额
    Quota        float64 `json:"quota"`         // 总配额
    UsedQuota    float64 `json:"used_quota"`    // 已使用配额
    Currency     string  `json:"currency"`      // 货币单位
    LastUpdated  int64   `json:"last_updated"`  // 最后更新时间
}

// BalanceError 余额查询错误信息
type BalanceError struct {
    Code    int    `json:"code"`
    Message string `json:"message"`
    Details string `json:"details,omitempty"`
}
```

### 5.2 扩展ChannelKey模型

```go
// 在现有ChannelKey中添加
type ChannelKey struct {
    // ... 现有字段
    Balance      *float64 `json:"balance,omitempty"`       // 余额（可选）
    LastCheckTime int64   `json:"last_check_time"`        // 最后检查时间
}
```

## 6. API设计

### 6.1 新增API端点

```
POST /api/v1/channel/query-balance
```

#### 请求参数
```json
{
    "channel_id": 123,           // 可选，指定渠道ID
    "force_refresh": false         // 可选，是否强制刷新缓存
}
```

#### 响应格式
```json
{
    "success": true,
    "data": [
        {
            "channel_id": 123,
            "channel_name": "测试渠道",
            "balance": 100.50,
            "quota": 1000000,
            "used_quota": 50000,
            "currency": "USD",
            "last_updated": 1704067200
        }
    ]
}
```

### 6.2 扩展现有API

在渠道列表接口中包含余额信息（如果有）。
